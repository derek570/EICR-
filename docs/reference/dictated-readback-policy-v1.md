# DictatedReadbackPolicyV1

`config/dictated-readback-policy-v1.json` is the versioned cross-client contract for CertMate’s spoken outcomes. Every accepted dictated reading or correction, requested calculation, and dictated reassignment produces one canonical scoped read-back. This duty does not depend on `confirmations_enabled` or model confidence. Typed edits, automatic derivations, side-effect ticks, address copies, and postcode locality enrichment remain silent.

The stored `cm-confirmation-mode` preference and wire `confirmations_enabled` field now mean **Extra prompts**. They may suppress plain ANSWERED acknowledgements, poor-signal advisories, “Feedback logged”, and optional orphan prompts. Questions, scripts, commands, declines, and the outcome owed after a chime remain audible. The controls say “Extra prompts on.” and “Extra prompts off. Readings still spoken.” A recording started with the preference off says “Extra prompts are off. Readings still spoken.” once at physical start.

The backend owns accepted Stage-6 and legacy read-back composition after validation. Clients apply local actions and replace any generic success narration with a value derived from the actual applied outcome. `applied`, `unapplied`, `failed`, and `unsupported` are the action outcome classes; only `applied` may claim the requested value landed. A web calculation whose Ze carrier cannot be read returns `unsupported: ze_unreadable` and says “I couldn’t apply that calculation.” Address mirror terminals keep their delivery token and complete atomic prose; an accompanying token-less voice-command frame owns only its action narration.

Exactly-once evidence counts playback starts rather than synthesis attempts. Mounted web tests count `getRecordingTestServices().ttsConfirmationPlayer.played` at `controls.onStart`. XCTest uses the inert `DeepgramRecordingViewModel._test_onConfirmationPlaybackStart` observer beside the production reservation/fast-played transition. `stage6` diagnostic `tts_speak_confirmation_called` rows count attempts only. Fake players and Simulator starts prove software delivery behavior, not that a person heard audio on an installed device.

The JSON file is canonical in the backend repository. XCTest reads the byte-identical copy at `Tests/CertMateUnifiedTests/Fixtures/dictated-readback-policy-v1.json` relative to `#filePath`. `scripts/check-dictated-readback-fixture-sync.sh` compares the two repositories byte for byte and is a required TestFlight preflight. Backend, web, and XCTest also pin the SHA-256 digest.
