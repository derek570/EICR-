## API Data Loading

The processing pipeline outputs separate JSON files, but the API can load from either format:
- **Pipeline outputs:** `installation_details.json`, `board_details.json`, `observations.json`
- **API also accepts:** `extracted_data.json` (combined format, created by PUT endpoint)

**Data Transformation:** When loading from pipeline files, `api.js` uses `transformExtractedData()` to map extracted data to UI format:
- Splits `board_details.json` into `board_info` + `supply_characteristics` + `installation_details`
- Maps fields like `ze` → `earth_loop_impedance_ze`, `voltage_rating` → `nominal_voltage_u`
- Sets sensible defaults for missing UI fields (e.g., `premises_description: "Residential"`)

If job data appears empty in PWA, check that API is reading the correct file format.

## Stage 6 Agentic Extraction (live recording path)

**Round-26 PLAN-2B scalar-compatibility closure.** A registered `mdr-*` clarification now reuses the shipped whole-reply-bounded scalar circuit parser before attempting an explicit ref list. Safe lead-ins such as *"Use/Choose/Pick circuit 2"*, *"Go with circuit 2"*, *"The answer is circuit 2"*, and *"I'd/I'll use circuit 2"* therefore pass the same shape gate and resolver on both transcript and direct-answer channels instead of remaining blocked until the 45-second timeout. Ordering is fail-closed: the existing exceptional qualifier lane runs first, correction/negation rejects before the scalar parser, then bounded scalar parsing runs before multi-ref parsing. Unowned *"Bedroom 2"* still preserves the ask, *"Do not use circuit 2"* reaches the correction terminal with zero writes, and value-bearing *"Add 0.4 to circuit 2"* releases/reinjects as fresh work exactly once.

**Round-25 PLAN-2B broker-lifecycle closure.** The effective-board freeze now covers collapsed `record_board_reading` mutations as well as per-circuit writes. A board write resolved from a main-board designation census therefore stays on main if `select_board` moves the cursor while the server-owned `mdr-*` question is open; its logical dedupe slot and any sibling `designation_no_match` notice retain the same frozen identity through the final survivor drain. The board dispatcher grants this exception only to an internal `::auto::` call whose board was genuinely selected when the census was taken, so model-authored scope for an unselected board still returns `wrong_board`. Global board-field winner stamps remain board-insensitive (`boardId:null`) after dispatch. A brokered `user_moved_on` also sets a server-owned generation latch: every later buffered-write ask in that stale dispatcher generation is suppressed before registry/emission even if the model changes `source_turn_id` or reformats the value; a fresh dispatcher starts with a clear latch.

**Round-24 PLAN-2B authority closure.** Frozen-board retention is not minted from a model-authored `context_board_id` or `pending_write.board_id`. At census time the dispatcher separately captures whether the resolved circuit board is the board the inspector actually has selected; only that server-observed fact can authorise the internal synthetic write to outlive a later cursor change. A model-scoped sub-board ask while main remains selected may inspect/resolve that census, but its generated writes traverse the ordinary `wrong_board` validator and mutate neither board. The legitimate main→broker-wait→select-sub exchange still writes its already-resolved targets to main without moving the cursor back.

**Round-23 PLAN-2B lifecycle closure.** A multi-description resolver exchange now freezes the effective circuit board before building its census. Every generated `record_reading` write, logical dedupe slot, follow-up ref check, and `designation_no_match` notice retains that board even if `select_board` changes `currentBoardId` while the registered `mdr-*` clarification is open. The normal write dispatcher still rejects model-authored wrong-board calls; only the internal synthetic auto-resolve route carries the frozen-board authority, and it does not move the user's selected-board cursor. If a fresh command overtakes the grouped clarification, the inner `user_moved_on` outcome abandons its unresolved ask entries and is surfaced additively as `followup_outcome:"user_moved_on"`. A generation-local buffered-write fence then answers any model retry with the same outcome without registering or emitting another stale ask, leaving the queued fresh command to reach the next harness exactly once.

**Round-22 PLAN-2B immutable-diff closure.** Literal stop-word designations now keep exact ownership through bounded answer wrappers as well as bare replies. After whole raw equality, a middle exact lane removes only edge discourse/articles, terminal `circuit|circuits|cct`, and edge politeness, then compares the remaining raw tokens without `STOP_WORDS`; *"the A circuit and B circuit"* therefore writes both refs, and scalar or registered `mdr-*` *"the A circuit"* resolves `A`, while a real stored name containing an article or `Circuit` still wins in the earlier raw lane. Short destructive-command evidence also requires at least one non-filler generic target token (or the explicit `circuit N` arm). Politeness/discourse such as *"delete please"*, *"remove, please"*, *"clear please"*, *"delete right"*, and *"clear yes"* preserves the blocked grouped clarification; the positive Ze/circuit/smoke-alarm commands retain immediate exactly-once release.

**Round-21 PLAN-2B immutable-diff closure.** Raw designation ownership now has a genuinely lossless exact pre-pass: it normalises case, punctuation, and enumerated separators but never removes `STOP_WORDS`, so a server-owned one-letter name such as *"A"* survives *"both A and B circuits"*, *"all A, B and C circuits"*, *"all three A, B and C"*, and the registered `mdr-*` follow-up. Only after that pre-pass misses does the existing filler-tolerant matcher handle forms such as *"the cooker circuit"*. The shared direct/transcript fresh-command classifier also has one anchored short action-plus-target lane for `delete`, `remove`, and `clear`; *"Delete Ze"*, *"delete circuit 3"*, and *"remove smoke alarm"* release a blocked grouped clarification immediately and traverse the harness exactly once, while a targetless action keeps the conservative fallback.

**Round-20 PLAN-2B immutable-diff closure.** A leading whole-list quantifier also owns an enumeration whose single `circuit(s)` noun appears only after the final separator: *"both Ground floor lighting and First floor lighting circuits"* and *"all A, B and C circuits"* use the list-wide path, while *"2 lighting circuits and the smoke alarm"* retains its attached first-span boundary. Explicit terminal-noun counts reconcile the complete distinct-ref set before mutation, so a mismatch writes nothing and stages no partial-success notice. Direct `ask_user_answered` overtakes now reserve both the stable utterance id and the short-lived canonical content anchor before synthetic transcript reinjection. A module-private owner symbol lets only that synthetic frame bypass the reservation across queue spreads; the ordinary paired transcript is suppressed in direct-first delivery, while transcript-first delivery makes the stale registry resolve fail and prevents a second synthetic copy.

**Round-19 PLAN-2B immutable-diff closure.** A list-wide quantifier that does not repeat the `circuit(s)` noun is parsed before per-span matching: *"both Ground floor lighting and First floor lighting"*, *"all three A, B and C"*, and their digit/number-word count forms fan out only when the total distinct resolved refs equals the requested count. A mismatch is a pre-mutation ask—zero writes and zero partial-success notices—rather than a partial resolve. Fresh-command detection is now one shared bounded classifier for transcript-prequeue and direct-answer frames; when a command arrives while an `mdr-*` clarification is blocked, the old ask is rejected with `mdr_new_command`, the in-flight turn unwinds, and the queued command drains exactly once. The scalar lane also retains bounded explicit-circuit lead-ins such as *"use circuit 2"*, *"go with circuit 2"*, and *"the answer is circuit 2"* while negations, values, and designation prose remain rejected.

**Round-18 PLAN-2B adversarial closure.** Three fail-closed boundaries supplement the multi-description contract below. A leading count or broadcast quantifier before `circuit(s)` does not launder command prose through quantifier stripping: *"1 circuit add 0.4 to Bedroom 2"* and *"all circuits add 0.4 to Bedroom 2"* write nothing, and both live answer channels reinject rather than consume the fresh command. A structurally complete fresh reading always overtakes an `mdr-*` scope ask before the generic exact `(field,circuit)` answer test, so even a coincident *"Ze is 0.22"* regex hit is new work. Follow-up capacity is checked against every supplied ref—including absent effective-board refs carried in resolver-only `supplied_circuit_refs`—before any mutation: a two-ref clarification answered with `5, 6, 99` dispatches zero writes, stages no partial-success notice, retains the ask, and emits one terminal. This metadata never enters a client frame.

Live recording flows through the Stage 6 agentic extraction pipeline. `config/field_schema.json` is the single source of truth for every extractable field; the tool schemas (`src/extraction/stage6-tool-schemas.js`) generate `record_reading.field` / `record_board_reading.field` enums from it at module load.

**Client-routing and structural rejection contract (PLAN-2D §3.6).** The live
field schema is no longer trusted as proof that a client can apply a reading.
`client-routable-reading-fields.js` commits the destination of every allowed
wire field, while structural keys, the three deliberately unroutable
sub-main keys, and correction-only aliases form the other three members of a
complete pairwise-disjoint dispatcher partition. Corrections are validated
against the same route manifest (`cpc_csa_mm2` → `cable_size_earth`;
`max_zs`/`ocpd_max_zs` → `ocpd_max_zs_ohm`), and a final egress guard drops
anything still off-manifest. Structural fields are refused before mutation:
positive distribution-link intent is recoverable only through
`mark_distribution_circuit`, whose same-turn success reconciles the notice;
all hierarchy edits and legacy sub-main writes are terminal, with the latter
directing the inspector to the Board tab. Board-attributed writes use their
own write-scope map rather than the narrower clear-scope map, so every
supported board field carries the server-resolved board independently of
`board_clear_v1`. The web router is deep-compared to the committed contract
and Swift pins the byte-identical fixture digest.

Sonnet's `ask_user` tool carries an OPTIONAL `pending_write` property. When the inspector says a value without enough context (e.g. "Number of points is 4" with no circuit), Sonnet attaches the buffered write to its ask. The server then:

1. Holds the user's reply.
2. Runs the deterministic answer resolver (`src/extraction/stage6-answer-resolver.js`) against the pending write + available circuits.
3. **High-confidence match** → server auto-emits the write through the normal write path (`createAutoResolveWriteHook` in `src/extraction/stage6-dispatchers.js`). Tool result body: `match_status: "auto_resolved", resolved_writes: [...]`. Sonnet doesn't write again.
4. **Low-confidence / ambiguous** → tool result echoes back `pending_write` + `available_circuits` + `parsed_hint`. Sonnet writes itself in the next turn.

**Multi-description circuit replies (PLAN-2B §3.3).** The plural DESCRIPTION MATCHING prompt steer is already on `main` from merged PR #133 (`5085614f`); PLAN-2B supplies its deterministic answer-resolution half. Before the scalar-number branch can consume only the first number, `resolveCircuitAnswer` detects enumerated/quantified multi-target syntax. It protects whole and embedded designations first: exact separator-canonical forms treat `&`, `+`, `and`, `plus`, and comma as equivalent only when one census designation owns the complete span; duplicate canonical designations ask, while the shipped single-target fuzzy match remains intact. Raw exact ownership is a separate first pass over every candidate span, so a shorter exact name cannot be swallowed by a longer span that becomes exact only after quantifier stripping; it also runs before filler and explicit-ref parsing, preserving real census names such as *"Right"*, *"OK"*, *"Done"*, and *"Bedroom 2"*. A bounded leading-retraction normaliser strips only outer punctuation and reply-opening `I said`/hedge wrappers before recognising negative auxiliaries and retraction verbs; it runs before both multi-target and scalar resolution, so a wrapped *"maybe I didn't mean circuit 3"* cannot become a write without stealing postfix qualifiers such as *"circuit 3 without the RCD"* from the scalar path. The resolver drops only unowned bounded conversational filler, then strips attached cardinal quantifiers plus `circuit(s)`, segments on enumerated separators, and fans out only exact/substring matches. An attached `circuit(s)` noun is a hard right boundary for its quantified span: *"2 lighting circuits and smoke alarm"* cannot swallow the following alarm, and a separator-bearing census name such as *"Lighting and Smoke Alarm"* cannot be claimed through the `lighting` component unless its whole raw name was actually spoken. Plain and `all <count>` quantifiers share one leading-cardinal parser: TENS+one-through-nine is considered before standalone TENS, and only a leading hyphenated compound is parsed, so 21/22 keep their full value without rewriting designation hyphens. Quantifier parsing retains an explicit malformed state across adjacent word/digit tokens, mixed hyphens and internal designation separators; therefore *"twenty ten kitchen lighting circuits"* and *"twenty-10 kitchen and utility lights circuits"* hard-escalate before any partial write. A real circuit named *"Two Lighting Circuits"* stays singular (duplicates ask), and only a plain valid count with empty designation residue such as *"two circuits"* returns to the shipped scalar path—`all`/`both` retain broadcast semantics and never collapse to one ref. An explicit plural quantifier with a real designation residue may promote all matching exact/substring candidates only when its count agrees; an unquantified ambiguity, fuzzy match, malformed compound, or count mismatch cannot fan out. The resolver returns successful sibling writes plus server-owned unresolved identities—census-backed circuit refs or stable one-based ordinals, never raw transcript text or an absent dictated ref. Mixed lists use the same fully anchored ref atom as the clarification, so prose such as *"Flat 2 sockets"* cannot become circuit 2 while an explicit *"circuit 2"* still can. The dispatcher builds the census from the effective board only (including unnamed circuits), writes/read-backs successful siblings, uses capacity-aware reconciliation so one candidate group cannot consume an unrelated unresolved entry, collapses all remaining ask-required entries into one registered and bounded `mdr-*` clarification, and routes an answer from either client answer channel through the resolver once. When one unquantified ambiguous source segment exclusively owns several suggested candidates, an explicit plural clarification may expand that segment to all successfully written candidates without a false unresolved apology; candidates shared across source segments retain forced capacitated reconciliation. Multi-description tool results use `match_status:"full"|"partial"|"all_unmatched"` plus the server-owned `unresolved[]`; any non-empty unresolved residue prevents a false full-success claim. The clarification alone accepts explicit ref lists while the ordinary resolver's legacy multi-number escalation stays unchanged; its fully anchored atom grammar accepts only bounded digit/number-word/compound/ordinal ref forms with optional circuit/cct/number wrappers and edge-only discourse filler, rejects residual tokens such as seconds or minutes, and validates every ref against the same board-scoped census. Answer attribution accepts that anchored ref/list, a census-backed designation of any match class, a bounded correction command, or an explicit spoken skip; timer chatter and other conversational filler preserve the exact ask, and a structured fresh reading overtakes it. The follow-up resolver itself writes only exact/unique-substring designations—ambiguous or fuzzy restatements are consumed immediately into one zero-write terminal and never fall through to the scalar C1 fuzzy path—while direct-answer outcomes retain the consumed utterance epoch. A failed broker emission, an answered clarification that leaves any target unresolved, or generation cancellation after a sibling write queues one generation-owned truthful terminal rather than ending silently. No-match entries stage PLAN-2A `designation_no_match` notices only after a sibling write succeeds, including combined circuit-ref and ordinal identities, and stage the same effective main/sub-board id that the successful `record_reading` journal entry carries. Normal cancelled turns still suppress partial-failure speech; the narrow PLAN-2B exception drains only `requiresSurvivingSibling` designation aggregates after rechecking that their same-slot sibling survived. An all-unmatched reply retains the previous escalation path with zero partial-success notices. This is server-only behaviour over the existing `ask_user_started` and field-nil confirmation frames.

Fresh-review correction closure is fail-closed at both resolver boundaries. The multi-target guard mirrors the live bulk-exclusion vocabulary for `apart from`, `except`, `excluding`, and `all but` before either scalar or fan-out resolution; a subtractive utterance therefore emits no deterministic write. Explicit commands including *"scratch that"*, *"forget that"*, *"correction"*, and *"make that …"* also terminate without a deterministic correction write, including when no target anchor follows. Bounded *"that is all"* / *"that's all"* suffixes remain conversational filler and cannot manufacture a no-match notice. Other registered `mdr-*` corrections still require an explicit circuit ref or known census designation before transcript-prequeue or direct-answer routing consumes them. Every accepted correction is rejected by the follow-up resolver with zero writes and one immediate terminal; targetless timer chatter such as *"wait 2 minutes"* preserves the ask. Spoken `skip`/`never mind`/`cancel` retains precedence over the substantive-designation branch and remains an ordinary opt-out with no apology.

The final fresh-context gate also closes ordering paths outside separator lists. Before scalar numeric parsing, a unique canonical whole designation owns its reply, so bare *"Flat 2 sockets"* or *"Bedroom 2"* cannot be redirected to circuit 2; the numeric fallback now accepts only a bounded whole-reply circuit-reference grammar. Its one shipped imperative exception is likewise bounded and explicit: *"Add to circuit 5 please"* and *"Put it on circuit 5"* remain circuit-ref answers, but only with an enumerated imperative, a `circuit`/`cct` noun, and one integer—designation prose, values, and multiple refs cannot use that lane. The shared designation-answer predicate permits the safe substring direction only (a short answer contained by one longer census designation); wider command/value prose that merely contains a real designation cannot reclaim it. After whole-exact designation ownership gets first refusal, an unmatched leading `add`/`put` target command fails closed before list segmentation, so *"Add to Bedroom 2"*, *"Add 0.4 to Bedroom 2"*, and *"Add to Bedroom 2 and circuit 5"* remain zero-write even when `Bedroom 2` is a live census name. The scalar resolver, grouped resolver, classifier, and both live answer channels share this rule. The registered `mdr-*` resolver and both live answer-channel predicates also reuse the exact bounded exception parser, including the separately enumerated *"circuit 3 without the RCD"* qualifier, so opening a grouped clarification cannot strand either shipped scalar answer form; every other correction/negation still fails closed. Digit and word quantifiers share the same count reconciliation and cannot enter the single-target fuzzy shortcut. When that reconciliation finds fewer candidates than the inspector requested, the registered spoken clarification names both the candidates found and the required circuit-reference count; the bounded answer then enforces the same count, so the audio instruction and resolver contract cannot disagree. Capacity enforcement happens before any follow-up write: if a two-ref clarification receives three valid refs, none of those follow-up writes dispatch and the bounded unresolved terminal is spoken. Only the documented unquantified ambiguous-description expansion can widen a one-slot entry, and only for candidates exclusively owned by that entry. Explicit `scratch that` / `forget that` / `correction` / `make that` commands are checked anywhere in the reply before numeric dispatch. Quantified matching and registered `mdr-*` answer attribution share canonical `&` / `+` / `and` / `plus` / comma equivalence; a deliberately excluded separator-bearing composite cannot be reclaimed through the scalar substring fallback.

For `record_board_reading`, the write array still collapses to one circuit-0 mutation. Resolver-only `selected_circuit_refs` retains the validated pre-collapse refs so grouped clarification can prove the requested scope was satisfied; it never enters a client frame. A partial no-match beside a successful board write resolves its trusted label from the board/supply/installation schema namespaces and scopes the notice from the projected `EFFECTIVE_BOARD_SLOT` winner: global Ze/PFC remain boardless, while a manufacturer write retains its selected main/sub-board identity. The drain accepts only safely attributed projected board winners as proof of partial success; a failed or symbol-less board write cannot mint a notice. After every awaited write the dispatcher rechecks generation ownership: fatal cancellation always propagates, and an interruption terminal is queued only when a successfully-started fan-out still has an unfinished target.

**Inverted asks — `pendingValue` + the `pvr-*` deterministic broker (field-feedback-2026-07-14 §A4).** `pending_write` covers the field-known shape (value expected in the answer). The INVERSE shape — value spoken, FIELD garbled, ask emitted with `context_field:"none"` — is covered by `pendingValue`: at ask registration the server captures the dangling value (`stage6-pending-value.js` `extractPendingValue` — unit-bound numbers preferred, circuit/board-adjacent numbers excluded as scope, multiple candidates → no capture) from the turn transcript (question fallback) onto the pending-asks entry, and copies it into the resolve outcome (the registry deletes entries before resolution runs). A field-name reply ("RCD trip time.") resolves via `resolveFieldNameAnswer` and dispatches `record_reading` through the SAME `createAutoResolveWriteHook` path (validation, wire canonicalisation, read-back bundling; board scope preserved via `write.board_id`). Unresolvable pieces re-ask DETERMINISTICALLY via a `pvr-*` broker that REGISTERS in the pending-asks registry BEFORE sending `ask_user_started` (a bare emit would orphan the answer; `srv-*` ids bypass the registry) — four-shape state machine (field ask / value ask / circuit ask / terminal), retry cap 1 per shape, terminal = an audible apology drained through `result.confirmations`. Both answer channels are guarded by the TYPED schema-aware fresh-reading detector (`detectStructuredReading`, all field families incl. select options+aliases, boolean vocab, assignment-form free text): a structurally complete fresh reading is an OVERTAKE (re-injected + written), never consumed as an ask answer. While a blocking ask holds `isExtracting`, `handleTranscript` classifies pending asks PRE-QUEUE (answers resolve-and-consume; evidence-backed moved-on rejects; everything else queues unchanged).

**Observation severity clarification chains (field-feedback-2026-07-14 §D2; mutation-to-chain correlation 2026-07-15).** Ambiguous C2-vs-C3 observations trigger ONE targeted factual `ask_user` (`context_field:"observation_clarify"`, `reason:"observation_confirmation"`). The ask budget for these is keyed per OBSERVATION, not per scope: the gate wrapper mints a `clarification_chain_id` on each initial ask (echoed in the tool_result; the model echoes it on the single bounded continuation), so two ambiguous observations at one scope get separate budget buckets while a chain's own third ask is blocked. Chains retire on observation mutation / audible termination / terminal fallback.

A post-answer write-or-reask net in the harness closes the beep-then-silence path when the model drops a clarified observation, independent of the A3 orphan net (which structurally cannot see this case). As of 2026-07-15 the net **correlates each write to its chain**: `record_observation` carries the echoed `clarification_chain_id` (nullable-required tool field; `null` for a direct/unclarified observation), the net GROUPS answered clarify asks by chain id (latest anchor per chain), and evaluates each chain once against events after ITS anchor — a matching successful `record_observation`, or a same-chain audibly-terminated continuation. "Successful" = `is_error !== true` AND a parsed tool-result body with `ok === true` (a parser that catches malformed bodies internally, never throwing into the net's outer catch). Mutation-id resolution is **LENIENT** on both edge cases (Derek 2026-07-15): an id-less write (D-1a) or an unknown/invented non-null id (D-1b) qualifies EVERY evaluated chain whose anchor precedes it — today's suppression outcome, chosen because a false "I didn't record that" apology → re-dictation → duplicate observation is a worse field failure than the residual (prompt-mitigated) suppression when the model omits the id; only a non-null id matching a DIFFERENT evaluated chain fails to qualify this one. All unqualified chains collapse into ONE count-aware field-nil fallback (singular vs plural wording); every evaluated non-null chain retires exactly once, after all qualification decisions. **Server-authoritative impedance clamp — the read-back speaks the STORED value (Plan D, 2026-07-25, feedback id 100(b) / session C06B9904; SAFETY-CRITICAL).** Deepgram Flux drops decimal points ("nought point six five" → "65"), so both clients carried a `clampImpedance` recovery that divided an out-of-band impedance by 10 then 100. It ran CLIENT-side, AFTER the server had already spoken: on a TN-C-S installation Derek dictated "Main earth is 16 now.", the server wrote the raw `16` and synthesised "Ze 16" from it, and the client silently stored `1.6`. The inspector heard a value 10× the one in the certificate — undetectable by ear, which is precisely what Audio-First #1 exists to prevent. The fix makes ONE actor authoritative: `src/extraction/impedance-clamp.js` clamps at every **pre-write** seam, so the snapshot, the emitted `readings` entry and the spoken confirmation are all synthesised from the SAME clamped number, and the correction is **named aloud** ("Ze recorded as 1.6 — I corrected 16 to 1.6") so a WRONG correction is catchable by ear. Ordering at each seam is `coerce → clamp → validate` (clamping before coercion would see un-normalised garble; after validation the range gate would already have rejected the raw value, defeating the point).

- **A hand-maintained JS mirror, not an import.** `packages/shared-utils` publishes raw TypeScript with no build output, the root manifest does not depend on it, backend Jest runs `transform: {}` with `moduleFileExtensions: ['js','json']`, and `Dockerfile.backend` never copies `packages/` — so this follows the established four-way-mirror precedent of `ios-dedupe-key.js`, pinned to `circuit-derivations.ts` by a reciprocal drift test.

The hoist is BOUNDED BY BOARD CONTEXT: `add_board` and `select_board` mutate `snapshot.currentBoardId`, and `record_board_reading` carries no `board_id` in its schema (its target board is resolved at dispatch time), so those two records pin in place and act as SEGMENT BOUNDARIES — the earthing-first partition applies WITHIN each run of non-context-changing records. Without that bound, "add the garage board, earthing is TT, Ze is 16" would stamp `TT` on the ORIGIN supply. `ask_user` is still tail-sorted globally: it writes nothing, so it has no board context to lose. Only `earthing_arrangement` is hoisted: it is a closed-enum FACT no other record consults for its own validation, so moving it cannot change any other record's outcome.
- **`out_of_range` is untouched** — the value is written unchanged and nothing is spoken about it. No new backend rejection path: inventing one would risk silently dropping a reading (Audio-First #2).

### Pre-LLM transcript gate (`src/extraction/pre-llm-gate.js`)

Every iOS transcript runs through `shouldForwardToSonnet(text, opts)` before the Sonnet round + TTS cost commits. The gate is a sequential pass with bypass and forward reasons emitted as `voice_latency.gate_blocked` (block) / `voice_latency.gate_forwarded_complaint` (positive) for ops dashboards.

`GATE_REASONS` enum (full list): `EMPTY`, `HAS_DIGIT`, `HAS_OBSERVATION_PREFIX`, `HAS_STRONG_TRIGGER`, `HAS_WEAK_TRIGGER`, `HAS_TRIGGER` (legacy, retained for back-compat), `HAS_REGEX_HINT`, `HAS_COMPLAINT_OR_NEGATION`, `HAS_EARTHING_SYSTEM`, `BORDERLINE_FORWARD` (A1, 2026-07-23), `LOW_CONTENT`, `FALLBACK_FORWARD`, plus bypasses `BYPASS_PENDING_ASK`, `BYPASS_DIALOGUE_SCRIPT_ACTIVE`, `BYPASS_IN_RESPONSE_TO`, `BYPASS_DRAINED_RETRY`, `BYPASS_DISABLED`.

`HAS_COMPLAINT_OR_NEGATION` (PLAN-backend-final.md §5.1) runs BEFORE `HAS_DIGIT` so complaints that accidentally contain digits ("you set it to 0.45 but I said 0.55") log with intent reason. The regex deliberately requires a continuation pronoun after a bare "no" so "no problem" / "no signal" / "no spare" still block via `LOW_CONTENT`.

**Borderline-forward (A1 agentic-voice, 2026-07-23).** When the session's latched `VOICE_AGENTIC_ANSWERS` flag is on, the terminal `LOW_CONTENT` drop becomes a FORWARD (`BORDERLINE_FORWARD`, `borderline: true`, logged as `voice_latency.gate_borderline_forwarded`): every server-received transcript corresponds to a client chime already fired (client gate PASS → chime → send), so a server-side content block was an un-nettable beep-then-silence — the block `return`s before `runShadowHarness` and the marker nets ever run. The server carries NO question word-lists, permanently — question detection is the MODEL's job (it answers via `answer_user`, no-ops chatter into the marker nets per the confirmation toggle, or writes an oddly-phrased reading). The call site resolves `entry.session?.agenticAnswersEnabled === true` (fail-closed: session-absent turns keep legacy `LOW_CONTENT` routing); the gate option defaults false. `EMPTY` still blocks on the ordinary path — Phase 0.5 proved production clients cannot send an empty transcript after a chime (both client gates block empty pre-chime) — and every bypass keeps its precedence. Economics: the gate's 2026-05-26 blocking rationale was Sonnet-priced turns (~$0.027); the live model is Haiku 4.5 with a cached prefix, and the measured server-side blocked volume was 1 turn/30 days (Phase 0.3, 2026-07-23) — borderline-forward costs <$0.02/month.

### Dialogue engine (`src/extraction/dialogue-engine/`)

Schemas: `rcd`, `ocpd`, `rcbo`, `ring_continuity`, `insulation_resistance`. Each is a script-style walk-through with entry triggers, per-slot prompts + parsers, defer / skip / cancel verbs, and a `toolCallIdPrefix` (`srv-rcd-` / `srv-ocpd-` / `srv-rcbo-` / `srv-irs-` / `srv-rcs-`).

The image is dewarped to a flat strip if `CCU_DEWARP_MAX_WIDTH` is set.
3. **Single-shot enumeration** — one OpenAI VLM call (`gpt-5.5` via `src/extraction/openai-vision-adapter.js`, ~4096 max tokens, ~15-20 s). Prompt: `MODERN_PROMPT` (DIN-rail boards) or `REWIREABLE_PROMPT` (BS 3036) in `src/extraction/ccu-single-shot.js`. The model receives the whole cropped rail image plus the prompt, and returns one entry per visible module slot in strict left-to-right order: `{device_kind, ocpd_rating_a, ocpd_curve, ocpd_bs_en, rcd_type, rcd_rating_ma, label}`. A 2-pole device returns two identical entries. Blanks return `device_kind:"blank"`. Labels are returned as a SEPARATE `labels[]` array with normalised `position_x` — the prompt forbids the model from assigning labels to devices itself; the code-side position matcher (`CCU_VLM_POSITION_MATCHER`, since 2026-05-21) does the label↔device assignment.
4. **Merge** — `slotsToCircuits` in `extraction.js` builds `circuits[]` from the single-shot entries: filters out `main_switch` / `spd` / `blank` so labels read on those positions never surface, and walks the slot order to attribute RCD-upstream relationships. Circuit 1 is nearest the main switch (BS 7671); side comes from (1) the single-shot's `main_switch` entry index, (2) rewireable `mainSwitchOffset`, (3) classifier's `main_switch_position`. SPD presence is derived from single-shot entries (any `device_kind:"spd"`); the classifier's `spd_present` is a pre-merger fallback only.
5. **Post-merge enrichment** — `applyBsEnFallback`, `normaliseCircuitLabels`, `lookupMissingRcdTypes` (web-search for RCD waveform type via `gpt-5-search-api`, fill-nulls-only, fires only when single-shot left it null AND both board manufacturer and model are known; the `uniform_low_conf` override trigger was REMOVED 2026-05-21 after clobbering correct AC reads on Crabtree Starbreakers); main-switch BS-EN/poles/voltage defaults. The SPD-from-main-switch supply fallback was removed 2026-06-17 — `spd_*` is the DNO cutout, a different physical device.
5b. **Quality gate** — `evaluateQualityGate` (`src/extraction/ccu-quality-gate.js`); fail ⇒ HTTP 422 `{status:'retake_required', reason, message, diagnostic}`. Hard signals: `poor_quad_fit` (rectNormCorr < 0.20), `too_many_nulls` (> 50% of OCPD circuits with unreadable rating — the OCPD filter understands both slot-shaped rows and live merged rows since 2026-07-08), and `classifier_low_confidence`. Since 2026-07-08 classifier confidence is a **soft** signal above a 0.65 hard floor: between 0.65 and 0.85 the gate passes anyway when the extraction corroborates itself (≥ 3 OCPD circuits, ≤ 50% null ratings). Rationale: Stage-1 confidence is a property of the board, not the photo (a Contactum board pinned 0.82 across three retakes with a perfect 13-circuit extraction), so a sub-0.85 score alone rejected every retake forever. Below 0.65 the gate still hard-fails regardless — the classifier may have routed the photo down the wrong prompt (modern vs rewireable). Deliberately NOT solved by improving board-model identification: model numbers have too much internal hardware variance to be a trustworthy signal.
6. **Response shape** — `circuits[]` (primary), `slots[]` (per-slot single-shot output reshaped for iOS LiveFillState consumption — crop bboxes are empty `{x:0,y:0,w:0,h:0}` and base64 is `""` because no per-slot crops exist), `geometric` (rail geometry + CV pitch diagnostics), `board_classification` (mirror of classifier output), `extraction_source: "geometric-merged"` (`"classifier-only"` only when single-shot produced no entries), plus the pre-existing top-level fields.

|---|---|---|---|

| Geometric prep (rail bbox + CV pitch) | local CV + 1 Sonnet call | ~3 s | ~$0.01 |

**Failure mode**: classifier or `prepareGeometry` failure returns 502. Single-shot failure (timeout, JSON parse, validation) first re-runs the request through the legacy per-slot path (`extraction.js` catch, logged as "falling back to per-slot"); `extraction_source: "classifier-only"` with empty `circuits[]` only when that also yields nothing.

**Legacy per-slot pipeline (LEGACY FALLBACK ONLY)**: `src/extraction/ccu-geometric.js`, `src/extraction/ccu-geometric-rewireable.js`, `src/extraction/ccu-label-pass.js` still exist and can be activated by setting `CCU_USE_SINGLE_SHOT=false`. They run a 4-stage Sonnet pipeline (rail bbox → CV pitch → per-slot crop+classify in batches of 4 → wider per-slot label-zone crop). Pre-2026-05-08 the live pipeline; retained for emergency rollback if single-shot regresses. **Do not reason about its behaviour as a current failure mode unless the env override is confirmed set.**

### CCU ground-truth review loop

Every extraction already persists its full-resolution source and raw answer at `ccu-extractions/{userId}/{sessionId}/{extractionId}/{original.jpg,result.json}`. The system-admin workspace at `/settings/admin/ccu-review?sample={opaqueId}` turns those diagnostic pairs into a review queue: the original photograph stays visible beside editable CertMate board/circuit fields, initially populated through the same `ccuAnalysisToCircuitRows` mapping used by the production apply path.

Saving writes a revisioned `ground-truth.json` beside the exact extraction. The session-level `final.json` is not treated as that photograph's truth because it may combine multiple boards or later voice edits; the detail API exposes it only as optional reference data. The admin-only API is `GET /api/admin/ccu-review`, `GET /api/admin/ccu-review/{sampleId}`, and `PUT /api/admin/ccu-review/{sampleId}`. All three are protected by `requireAuth` + `requireAdmin`; image bytes are exposed through a 15-minute S3 URL. Review payloads use field allowlists, strip stored crop/base64 diagnostics, and never expose the source user id. `storage.listFiles()` paginates S3 so the queue remains complete beyond the 1,000-object ListObjectsV2 page size.
